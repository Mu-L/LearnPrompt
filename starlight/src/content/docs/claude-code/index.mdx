Claude Code 的价值不在于多开几个会话，而在于它能否在真实仓库中读懂规则、完成小改动、留下检查证据，并在需要时停下来等你决定。

## 从什么问题开始

| 你现在遇到的事 | 先读 | 第一个可验收结果 |
| --- | --- | --- |
| 第一次在本地项目使用 Claude Code | [安装与第一个项目](./install-and-first-project/) | 一个可丢弃仓库里的最小改动闭环 |
| 团队规则总靠重复口头说明 | [用 CLAUDE.md 控制协作风格](./control-style-with-claude-md/) | 一份范围明确的项目规则 |
| 会话很长、结果开始漂移 | [进阶对话模式](./advanced-conversation-patterns/) | 一条带状态与验收的续办路径 |

## 一条可复用的学习路线

1. 先在可删除的 Git 小项目里跑通安装、登录、任务、改动和验收，不要直接碰生产项目。
2. 把项目规则写进 [最小 CLAUDE.md](./minimum-claude-md/)，让任务范围、测试和停止条件能被重复读取。
3. 只有当流程反复稳定出现时，再学习 [Skills、Hooks、MCP 与角色](./skills-hooks-mcp-roles/) 的边界与组合。

## 读完要留下什么

- 一个能安全练习的本地仓库和最小验收命令。
- 一份只约束当前项目的 CLAUDE.md，而不是一份泛泛的提示词。
- 一条发生失败后还能继续定位、复盘和交接的路径。

## 继续前进

如果你的任务同时需要 Codex，先读 [Claude Code 与 Codex 的双轨工作法](../codex/codex-claude-code-dual-track/)。当协作规模变大时，再引入明确的角色、独立审查和合并边界。
