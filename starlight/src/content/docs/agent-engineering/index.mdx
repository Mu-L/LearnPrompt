Agent 做错事时，原因通常不只是模型不够聪明。规则是否被读到、工具是否可用、权限是否越界、状态是否丢失、反馈是否能进入下一轮，都会决定结果。

## 从什么问题开始

| 你现在遇到的事 | 先读 | 第一个可验收结果 |
| --- | --- | --- |
| Agent 能做事但总做不稳 | [Harness 的五个组件](./what-is-harness/) | 一份按组件定位的系统检查 |
| Agent 不断遗漏项目规则 | [指令层](./instruction-layer/) | 一份可读取、可审计的指令面 |
| Agent 反复遗忘已验证的状态 | [记忆层](./memory-layer/) | 一份能跨轮次继续使用的状态记录 |

## 一条可复用的学习路线

1. 先区分任务失败来自模型推理，还是来自指令、工具、权限、状态或验收合同缺失。
2. 用 [约束层](./constraint-layer/) 写清绝对不能跨越的动作，并让高风险步骤进入明确的确认门。
3. 再用 [反馈层](./feedback-loop/) 把测试、审查和真实环境信号接回下一轮，而不是只收集一条“完成了”。

## 读完要留下什么

- 一张当前 Agent 系统的指令、能力、约束、状态和编排地图。
- 一项可以通过命令、fixture 或人工检查验证的失败假设。
- 一条发现异常后能停止、记录并进入下一轮的反馈路径。
