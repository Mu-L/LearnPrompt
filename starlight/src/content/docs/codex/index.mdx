同一个 Codex 任务放在不同执行面，能看到的文件、能调用的工具、等待反馈的方式和需要的人审都不一样。先选对工作场地，才谈效率。

## 从什么问题开始

| 你现在遇到的事 | 先读 | 第一个可验收结果 |
| --- | --- | --- |
| 不知道该用 CLI、IDE、桌面还是 Cloud | [Codex 的四个执行面](./codex-form-factors/) | 一张任务与执行面的匹配表 |
| 想在终端完成一次安全的小改动 | [Codex CLI 工作流](./codex-cli-workflow/) | 一次带 diff 和检查的本地交付 |
| 不确定沙箱、网络与权限的边界 | [沙箱与权限](./sandbox-and-permissions/) | 一份任务需要的最小授权清单 |

## 一条可复用的学习路线

1. 先按本地反馈、异步等待、代码访问和风险等级选择执行面，而不是按“哪个更强”选择工具。
2. 给每次执行写清哪些命令和外部动作可以做，哪些必须停下来等确认。
3. 用 [自动审查的边界](./auto-review-boundaries/) 把“发现问题”和“替人合并、发布或删除数据”分开。

## 读完要留下什么

- 一份任务、执行面、权限和验收方式的选择记录。
- 一次可回看的 diff、命令输出和未解决风险。
- 一条在需要人审或外部授权时能够明确停止的规则。
