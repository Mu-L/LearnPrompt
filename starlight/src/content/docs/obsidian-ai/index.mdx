把资料放进 Obsidian，不会自动让 Agent 拥有记忆。可靠的知识工作流需要清楚的目录角色、可读的入口、可审查的候选改动，以及能让新会话继续的交接记录。

## 从什么问题开始

| 你现在遇到的事 | 先读 | 第一个可验收结果 |
| --- | --- | --- |
| 不确定怎样给 Agent 放置材料 | [Vault 目录怎样才对 Agent 有用](./vault-directory-for-ai/) | 一份目录角色与拒绝边界合同 |
| 想让新会话接上上次项目 | [Markdown 何时才算 Agent 记忆](./markdown-as-agent-memory/) | 一份 fresh Agent 可继续的 handoff packet |
| 想用 Git 审查 Agent 批量改动 | [Obsidian + Git 工作流](./obsidian-git-workflow/) | 一道 clean baseline 与 diff 验收门 |

## 一条可复用的学习路线

1. 先规定资料、项目状态、输出和系统规则各自应该放在哪里，而不是让 Agent 搜遍整个 vault。
2. 用 [CLAUDE.md 索引导航](./claude-md-index-navigation/) 让读取路径可预测，并区分规则文件与普通知识笔记。
3. 用 Git 和可验证 handoff 把候选改动、已接受决策和下一条命令留下来，再让下一位协作者继续。

## 读完要留下什么

- 一套目录角色、canonical path 和敏感材料拒绝规则。
- 一份标有状态、证据、限制和下一条命令的交接记录。
- 一道把“Agent 说完成”与“人已验收”分开的 Git 检查门。
