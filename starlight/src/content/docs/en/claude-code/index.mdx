The value of Claude Code is not opening more sessions. It is whether it can understand a real repository's rules, complete a small change, leave check evidence, and stop when a decision belongs to you.

## Start with the problem you have

| What is happening now | Read first | Your first verifiable result |
| --- | --- | --- |
| You are using Claude Code in a local project for the first time | [Installation and your first project](./install-and-first-project/) | A minimal change loop in a disposable repository |
| Team rules rely on repeated verbal explanations | [Control collaboration style with CLAUDE.md](./control-style-with-claude-md/) | A project rule with a clear scope |
| Sessions grow long and the result starts to drift | [Advanced conversation patterns](./advanced-conversation-patterns/) | A continuation path with state and verification |

## A reusable learning route

1. First complete installation, sign-in, a task, a change, and verification in a deletable Git project instead of touching production work.
2. Put project rules in a [minimal CLAUDE.md](./minimum-claude-md/) so scope, tests, and stopping conditions can be read again.
3. Only after a workflow repeats reliably, learn the boundaries and composition of [Skills, Hooks, MCP, and roles](./skills-hooks-mcp-roles/).

## What to keep after reading

- A safe local repository for practice and a minimal verification command.
- A CLAUDE.md that constrains this project, rather than a vague generic prompt.
- A path that can still locate, review, and hand off work after a failure.
