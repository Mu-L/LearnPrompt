## How to use this page

This is not a copy of every footnote on the site. It is a source map. Each in-depth tutorial records its verification date and keeps the links actually used, together with their applicable boundaries, at the bottom of the page. This page helps you decide which kind of source to revisit when checking a claim.

LearnPrompt divides evidence into three tiers:

| Tier | Primary purpose | What it cannot prove on its own |
| --- | --- | --- |
| Primary sources | Verify product capabilities, commands, permissions, specifications, versions, and release status | They do not automatically prove that an article example fits your project |
| Secondary topic maps | Discover problem spaces, cases, and learning structures | They cannot replace current official facts or automatically grant permission to republish |
| Field experiments | Prove a specific Showcase with frozen fixtures, scripts, receipts, and reviews | They cannot be generalized to every version, environment, or permission combination |

## Orange Book attribution and licensing boundaries

The Orange Book repositories above are maintained by Huashu (Huashu / GitHub `alchaincyf`) and are important topic maps for this curriculum redesign. LearnPrompt does not hide that influence by removing attribution or sources.

As of 2026-07-12, we read the `LICENSE` and README on each repository's current default branch and obtained the license matrix below. A GitHub API `spdx_id: null` or `NOASSERTION` only means the platform did not recognize a standard SPDX identifier; it does not establish that a repository declares no license.

| Repository | Current declaration | Boundary when using it |
| --- | --- | --- |
| Claude Code Orange Book | README: CC BY-NC-SA 4.0 | May be shared and adapted under that license; attribution, non-commercial use, and ShareAlike are required |
| Claude Code Source Analysis Orange Book | README: for education and research only, with trademark and leaked-code disclaimers | A custom statement; do not expand it into a standard open license |
| Codex Orange Book | README: CC BY-NC-SA 4.0 | May be shared and adapted under that license; attribution, non-commercial use, and ShareAlike are required |
| Harness Engineering Orange Book | README: for learning and discussion only; cite the source when quoting | A custom statement; it does not automatically allow commercial redistribution or adaptation |
| Agent Skills Orange Book | README: personal and educational use; no commercial redistribution without authorization | Custom, non-commercial personal and educational-use boundaries |
| Loop Engineering Orange Book | Repository `LICENSE`: MIT | May be used, copied, modified, and distributed under MIT, while retaining the license text |
| Obsidian AI Orange Book | README: for learning and discussion; republication and quotation welcome with attribution | A custom attribution-and-sharing statement, not equivalent to CC/OSI licensing |
| Hermes Agent Orange Book | Current repository `LICENSE`: MIT; README says 2.0 changed from the earlier CC BY-NC-SA 4.0 to MIT | Current version is MIT; still check the corresponding version when citing older materials |
| OpenClaw Orange Book | README: content is for educational use only and related trademarks belong to their owners | A custom statement; it does not automatically permit copying, adaptation, or commercial distribution |

Licenses apply to the material each repository covers; they do not automatically cover third-party screenshots, trademarks, upstream code, or externally linked assets.

Accordingly, this project uses the following conservative boundaries:

1. Orange Books are used for topic selection, problem maps, and leads to verify.
2. Volatile facts return to primary sources or field experiments; descriptions in the books are not treated as current truth.
3. PDF body text, screenshots, and images without an explicit covering relationship are not copied into public tutorials; third-party assets must also be excluded from MIT or CC repositories.
4. When using material expressly authorized by a repository, record the author, original link, version, license, modification method, and verification date item by item; do not infer a license for an entire series from one book.
5. Keep the actual Orange Book links used by, and the applicable boundaries for, every article at its bottom.

## LearnPrompt's own field evidence

Every verified in-depth tutorial has a `research/` directory containing at least:

- `brief.md`: the reader task, scope, and non-goals.
- `horizontal-research.md`: adjacent approaches, differences, and applicability boundaries.
- `vertical-research.md`: a vertical evidence chain for key concepts.
- `evidence-ledger.md`: a mapping between body claims and sources.
- `asset-ledger.md`: image sources, licenses, modifications, and visual checks.
- `review.md`: an independent reviewer's itemized conclusions, findings, and final verdict.
- `showcase/`: frozen fixtures, scripts, outputs, and rejection cases; individual files are organized as each article requires.

The research directory records how an article reached its conclusions; it is not a mirror of source material. Public MDX does not display an independent source-card component, but removing that component does not mean removing the sources.

## How versions and broken links are handled

- Product capabilities, commands, prices, permissions, and releases are high-drift information and are used according to the article's verification date.
- An automated external-link check returning `403` only means the automated request was blocked. It must be checked manually in a browser and must not be marked valid or broken directly.
- Deep research links that have not reached a public branch do not pass a publication-candidate gate; verify them after pushing, or replace them with stable links before publication.
- When an official page moves, update it first to the current page on the same official domain, and retain the old link and reason for the change in the research record.
